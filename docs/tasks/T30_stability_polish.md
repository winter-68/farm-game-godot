# T30：MVP+ 稳定性与体验修复

> 基于已完成并打 tag 的 T0–T29 基线。此任务只处理回归发现的问题，不新增玩法系统。

## 任务目标

集中修复完整回归中发现的 UI、输入、存读档兼容和 Godot 4.3 实机问题，保持现有农场循环、季节、天气和收集系统行为不变。

## 实现原则

- 每次只修复一个明确问题，修复前先记录复现步骤。
- 只修改当前问题涉及的文件，不顺手重构其他系统。
- 不改变 EventBus 信号名、现有数据结构和存档字段含义。
- 保持占位色块，不引入外部美术、音频或第三方插件。
- 修复后必须在 Godot 中回归验证，并确认控制台没有红色报错。

## 首轮检查清单

### UI 与层级

- 确认 CollectionToast 位于 UI 最上层，但不遮挡 HUD、商店、背包和收集面板的可操作区域。
- 确认底部 Toast 与 Hotbar 的位置不会造成严重重叠。
- 确认 CollectionUI、InventoryUI、ShopUI 在 320×180 视口中完整可见。
- 确认天气 Overlay、季节提示和收集 Toast 的提示位置互不冲突。

### 输入

- J：use_tool
- C：toggle_collection
- B：toggle_shop
- Tab：toggle_inventory
- Enter：debug_sleep
- 空格：interact / 收获
- 确认打开任一面板后，移动、工具、商店和存档快捷键行为符合预期。

### 存读档与兼容

- 新游戏、保存、退出、继续游戏完整回归。
- 读档后农田、作物阶段、天气、季节、背包、金币、图鉴和成就全部恢复。
- 读档期间不重复触发成就 Toast。
- 缺少可选的新字段时旧存档不会崩溃。
- 确认 Godot 4.3 运行无 API 或场景解析错误。

## 验收标准

- 完整回归流程无红色报错。
- 所有输入动作无冲突。
- 所有 UI 在目标视口内可读、可关闭、可继续操作游戏。
- 存读档前后状态一致，且不会重复刷成就或 Toast。
- 修复范围清晰，未修改无关管理器、数据类或场景。
